# 1. 计算机系统与程序执行

应用程序的执行依赖硬件与软件共同协作。处理器执行指令，内存保存程序和数据，磁盘与网络提供存储和通信能力。编译器把程序翻译为机器代码，操作系统管理运行所需的资源，库和网络协议提供程序可以使用的功能与通信约定。

编程语言、数据结构和算法分析通过抽象简化了程序设计。分析具体错误或性能问题时，还需要理解这些抽象在底层如何实现，以及它们适用的条件。例如，数值类型的表示范围会影响运算结果，数据在内存中的位置会影响越界访问的后果，访问顺序会影响程序运行时间。

# 2. 有限精度下的整数与浮点运算

## 2.1 整数表示范围与溢出

计算机用有限个二进制位表示数值，可表示的整数范围因此受到限制。以 32 位有符号整数为例，其范围为 $-2^{31}$ 到 $2^{31}-1$，最大值为 $2147483647$。

数学上的平方运算总能得到非负整数，但用固定宽度的整数类型计算时，还必须考虑结果是否能被表示。

| 表达式 | 数学结果 | 是否在 32 位有符号整数范围内 |
| --- | --- | --- |
| `40000 * 40000` | $1600000000$ | 是 |
| `50000 * 50000` | $2500000000$ | 否 |

当运算结果超出类型的表示范围时，就发生了**溢出（Overflow）**。在 C 中，有符号整数溢出属于未定义行为，语言没有规定此时应得到哪个结果。因此，判断整数表达式的行为时，需要同时考虑数值范围和语言对溢出的规定。

## 2.2 浮点舍入与运算顺序

浮点数用有限个二进制位近似表示实数，能保留的有效数字也有限。一个很大的数与一个很小的数相加时，较小的数可能因舍入而丢失，改变加法顺序便可能改变结果。

例如，在通常的双精度浮点运算下，下面两种计算顺序会得到不同的结果。

```text
(1e20 + -1e20) + 3.14  → 3.14
1e20 + (-1e20 + 3.14)  → 0
```

第一种顺序先把两个大小相等、符号相反的数相加，得到零，再与 `3.14` 相加。第二种顺序先计算 `-1e20 + 3.14`，由于 `3.14` 相对于 `1e20` 太小，在有限精度下被舍去，内层结果仍为 `-1e20`，再与 `1e20` 相加得到零。

这里的差异来自浮点表示与舍入规则。浮点加法不满足结合律，数学上等价的表达式在机器上可能产生不同结果。

# 3. 汇编与机器级执行

**汇编语言（Assembly Language）**用文本形式表示机器指令。编译器把高级语言程序翻译为机器代码，处理器通过这些指令完成数据读写、算术运算和控制转移。

阅读汇编可以观察程序实际执行的操作，以及编译器生成了怎样的代码。这有助于理解几类问题。

- **底层错误。** 当错误涉及内存覆盖或执行状态时，需要观察具体的访存和控制转移操作。
- **程序性能。** 通过生成的指令，可以检查编译器完成了哪些优化，以及哪些操作仍在重复执行。
- **系统软件。** 编译器需要生成机器代码，操作系统需要管理程序执行时的状态，这些工作都与机器级执行模型有关。

# 4. 内存管理与越界访问

程序使用的内存容量有限，需要分配和管理。C 和 C++ 中的数组访问、指针操作以及动态内存分配还可能引入内存引用错误，例如数组越界、使用无效指针或错误地调用 `malloc`、`free`。这类错误可能破坏其他数据，直到后续使用这些数据时才表现出来。

下面的结构体包含一个有两个元素的整数数组 `a`，以及一个浮点成员 `d`。函数先把 `d` 设为 `3.14`，再向 `a[i]` 写入一个整数，最后读取 `d`。

```c
typedef struct {
    int a[2];
    double d;
} struct_t;

double fun(int i) {
    volatile struct_t s;
    s.d = 3.14;
    s.a[i] = 1073741824;
    return s.d;
}
```

`a` 的有效下标只有 `0` 和 `1`。以 `int` 占 4 字节、`double` 占 8 字节，且 `d` 紧接在数组之后的布局为例，各成员的位置如下。偏移量从结构体起始地址计算。

| 字节偏移 | 存放的成员 |
| --- | --- |
| 0～3 | `a[0]` |
| 4～7 | `a[1]` |
| 8～15 | `d` |

若执行越界写入时仍按每个数组元素占 4 字节计算地址，写入 `a[2]` 和 `a[3]` 就会覆盖 `d` 的部分字节。随后读取 `d` 时，得到的值可能已经改变。更远的越界写入还可能破坏其他状态，导致程序崩溃。

例如，在上述布局的一次特定系统运行中，`fun(0)` 和 `fun(1)` 返回 `3.14`，`fun(2)` 返回约 `3.1399998664856`，`fun(3)` 返回约 `2.00000061035156`，而 `fun(6)` 触发了段错误。段错误是访问内存时触发的一类运行错误，可能导致程序终止。

越界访问属于未定义行为，具体表现取决于编译器、系统和运行时状态。一次运行中返回值看似正常，也无法据此判断访问有效。定位这类错误，需要追查错误写入与被破坏数据之间的关系，必要时使用 Valgrind 等内存错误检测工具。

# 5. 访问模式对程序性能的影响

算法的渐近复杂度描述输入规模增长时计算量的变化。对于执行相同数量操作的程序，实际耗时还会受到编译结果、数据布局和内存访问模式的影响。

下面两个函数都把一个 $2048\times2048$ 的二维数组复制到另一个数组，区别在于内层循环改变哪个下标。

```c
void copyij(int src[2048][2048], int dst[2048][2048]) {
    for (int i = 0; i < 2048; i++) {
        for (int j = 0; j < 2048; j++) {
            dst[i][j] = src[i][j];
        }
    }
}

void copyji(int src[2048][2048], int dst[2048][2048]) {
    for (int j = 0; j < 2048; j++) {
        for (int i = 0; i < 2048; i++) {
            dst[i][j] = src[i][j];
        }
    }
}
```

C 的二维数组按行连续存储。`copyij` 固定行下标 `i`，让列下标 `j` 连续变化，依次访问同一行中相邻的元素。`copyji` 固定列下标 `j`，让行下标 `i` 连续变化，相邻两次访问会跨过一整行的距离。

内存系统通过多级存储和缓存缓解访问速度的差异。**缓存（Cache）**在靠近处理器的位置保存部分数据，访问缓存中的数据通常比访问主存更快。程序倾向于访问相邻地址的性质称为**空间局部性（Spatial Locality）**，重复使用近期访问过的数据的性质称为**时间局部性（Temporal Locality）**。

`copyij` 连续访问一行中的元素，更容易利用缓存中已经取入的相邻数据。`copyji` 跨行访问，对缓存的利用情况可能明显不同。在一台 2.0 GHz Intel Core i7 Haswell 处理器上的测量结果如下。

| 函数 | 内层循环的访问方向 | 运行时间 |
| --- | --- | --- |
| `copyij` | 沿同一行访问 | 4.3 ms |
| `copyji` | 沿同一列访问 | 81.8 ms |

两个函数复制的元素数量相同，访问顺序却带来了明显的时间差异。这组时间与具体测试环境有关。分析和优化程序时，需要结合实际测量，检查算法、数据表示、函数和循环各层面的开销。

# 6. 输入输出与网络通信

**输入输出（Input/Output，I/O）**负责让数据进入或离开程序，例如读取磁盘文件、接收用户输入和输出结果。I/O 系统的行为会影响程序的可靠性和性能。

网络把数据交换扩展到不同计算机之间。网络程序需要处理多个独立程序同时推进操作的情况，也就是**并发（Concurrency）**，还需要应对不可靠的通信介质、不同平台之间的兼容性以及通信带来的性能问题。双方必须遵循共同的通信约定，才能正确解释交换的数据。
